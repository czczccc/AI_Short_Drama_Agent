# Execution Plan: Interview Text MVP

## 1. 目标与控制模型

当前目标是把现有文字生产链封板为可面试演示的后端 MVP，而不是继续增加 Agent 或提前进入视频。

- `docs/03_development/TASKS.md`：路线、状态和验收标准的唯一事实来源。
- `tasks/plan.md`：DeepSeek维护的依赖图、自主执行协议和阶段 Runbook。
- `tasks/todo.md`：当前单任务包或受控批次清单；任何时刻只能有一个活动批次。
- `tasks/queue/`：由 DeepSeek维护的批次原子任务包；按 `todo.md` 和依赖门禁执行。
- `tasks/text_backlog.md`：文字端从当前状态到面试封板的完整原子任务目录；只供预读和后续激活，不授予越级执行权限。
- `tasks/execution_log.md`：DeepSeek execution/self-review 与可选外部 review 的追加式证据日志，不控制任务状态。

角色分工：

- **DeepSeek / 总体负责人兼执行者**：维护路线与任务，实施、测试、自审、更新状态并继续下一任务。
- **用户 / 决策者**：批准产品目标、封板标准、非文字扩展、密钥和破坏性操作。
- **Codex / 可选顾问**：仅在用户主动要求时提供额外审查，不构成任务门禁。

## 2. 不可违反的执行协议

1. 单任务模式一次执行一个原子任务；批次模式只执行 `tasks/todo.md` 明列的有序队列，不接受“顺便修复”。
2. 开始前读取 `AGENTS.md` 以及任务包列出的最小上下文，不一次加载全部文档。
3. 优先补测试或增强断言；测试已经覆盖且通过时，不为了制造改动而重写生产代码。
4. 只能修改任务包的文件白名单；需要越界时停止并报告，不自行扩大范围。
5. 不得重置、覆盖或删除当前工作区已有改动；不得修改 `.env`、调用真实模型、commit 或 push，除非任务包明确授权。
6. DeepSeek 完成或阻塞后，必须追加 execution 和 self-review 记录；通过自审后自行同步 `TASKS.md`、`plan.md` 和 `todo.md`，不得修改历史记录。
7. 执行日志不得包含 API Key、`.env` 内容、完整 Prompt、完整模型输出或无关的大段测试日志。
8. 批次自动继续的前提是当前任务完成、指定测试全过、没有生产代码修改且 `AUTO_CONTINUE: yes`；否则立即停止。
9. DeepSeek 必须在状态更新前检查整批 diff、重跑必要测试并追加 self-review；用户要求时再交由 Codex 额外复核。

## 3. Definition of Ready

原子任务只有同时满足以下条件才能交给 DeepSeek：

- 有唯一任务 ID、单一目标和明确非目标。
- 依赖任务已经通过 DeepSeek 自审并在 TASKS 中标记完成。
- 默认修改不超过 1–2 个文件；超过 5 个文件必须重新拆分。
- 指定了允许读取/修改的文件、测试命令和可观察验收结果。
- 写明停止条件和需要回报的证据。

## 4. Definition of Done

任务只有同时满足以下条件才能由 DeepSeek 标记完成：

- diff 只包含授权范围内的必要修改。
- 验收标准均由测试或只读证据证明，不以“代码看起来正确”代替。
- 指定测试通过，没有跳过或删除既有测试。
- 没有新增 LLM 调用、依赖、API、数据库字段或兼容分支，除非任务明确要求。
- DeepSeek 已追加执行记录，包含修改文件、实施方法、测试命令、结果和剩余风险。
- DeepSeek 已完成 diff 自审并追加 self-review；用户要求额外审查时再补外部 review。

Phase 完成还必须运行全部 pytest，并同步该 Phase 实际影响的 API/工作流/模型文档。原子任务完成不等于 Phase 完成。

## 8. 执行与复核日志

DeepSeek 每次执行完成或阻塞后，把同一份结构化报告追加到 `tasks/execution_log.md`，并在对话中返回摘要。记录 ID 使用：

```text
<TASK_ID>/attempt-<N>
```

DeepSeek 自审后追加 `<TASK_ID>/self-review-<N>`，不得回写或修改原 execution 记录。用户另请顾问审查时可追加 `<TASK_ID>/review-<N>`。执行日志记录事实证据，任务状态仍只由 `TASKS.md` 控制。

## 9. DeepSeek 回报格式

DeepSeek 每次必须按以下格式返回，缺一项视为未交付：

```text
TASK_ID:
RESULT: completed | blocked
FILES_CHANGED:
- path: purpose
TESTS_RUN:
- exact command
- exact result
ACCEPTANCE_EVIDENCE:
- criterion: evidence
NOT_CHANGED:
- out-of-scope areas preserved
RISKS_OR_BLOCKERS:
- none, or exact blocker
```

禁止只回复“已完成”“测试通过”或只贴代码片段。

## 10. 停止条件

DeepSeek 遇到以下任一情况必须停止并回报用户：

- 需要修改任务包白名单之外的文件。
- 需要新增 API、Schema、数据库字段、依赖或 LLM 调用。
- 发现现有未提交改动与任务修改发生冲突。
- 指定测试之外出现失败，且根因不属于当前验收标准。
- 需求存在两种会产生不同业务行为的合理解释。

## 11. 风险控制

| 风险 | 控制方式 |
|---|---|
| 执行者顺手扩范围 | 单任务文件白名单 + 停止条件 |
| 文档和实际状态不同步 | DeepSeek 自审通过后同步唯一状态源 |
| 执行过程无法追溯 | DeepSeek 分别追加 execution/self-review 记录 |
| 真实模型反复试错烧费 | 每个修复默认一次针对性真实复测 |
| 长任务无法定位失败 | 单集、分段、分题材检查点 |
| 当前脏工作区被覆盖 | 禁止 reset/checkout/批量覆盖；只在已验证检查点提交 |
| 面试封板时大重构 | S3-9 只做有证据的瘦身，不改核心行为 |
