# AI Short Drama Agent 项目地图

## 一句话定位

这是一个 AI 短剧生产流水线：你把一句故事创意交给它，它自动帮你把整部短剧写出来——从大纲、角色设定到每一集的完整剧本，并且自己检查前后剧情是否连贯、伏笔是否兑现。

## 核心流程

```
创意
↓
Director（导演）——把一句话创意扩成 10 集分集大纲
↓
Character（角色）——根据大纲定出每个角色的性格、动机、关系
↓
Showrunner（总控）——定整季走向 + 给每一集下发"本集任务书"
↓
Writer（编剧）——按任务书写出这一集的完整剧本
↓
QC（质检）——检查剧本质量：机器查硬规则、AI 查剧情逻辑、
             所有结论必须能在剧本原文找到证据，不过就打回重写
↓
Memory（记忆）——把这一集浓缩成"剧情记忆"，供下一集参考
↓
（循环）——每一集都走 任务书→写剧本→质检→存记忆
```

整个流程的核心思想：**每一集都不是一次写成的，而是"写 → 查 → 改 → 过"的循环**，保证 10 集连起来讲的是一个自洽的故事。

## 核心模块

```
API：
负责接收请求
——用户点一下"生成剧本"，它接住这个动作并转发下去

Service：
负责流程编排
——"车间主任"：决定先加载什么、调哪个 Agent、结果怎么合并、
  什么时候落库、不通过怎么返工

Agent：
负责调用 LLM 完成任务
——"熟练工"：选好提示词和输出格式，让大模型干一件事
  （写大纲/写角色/写剧本/质检），并对结果做校验

Provider：
负责模型适配
——"通信员"：全项目唯一的"给大模型打电话"的人
  换模型只改它一个文件

Database：
负责保存状态
——记住一切：大纲、角色、每集剧本、剧情记忆、质检报告
```

## 分层原则

每一层只关心一件事：

- 上层说"我要什么"，不关心"怎么实现"
- 下层说"怎么实现"，不关心"为什么需要"

## 快速提问对照表

| 你想问 | 答案在哪 |
|---|---|
| 用户怎么操作 | `app/api/` 各路由文件 |
| 业务流程怎么编排 | `app/services/` |
| AI 怎么生成内容 | `app/agents/` + `app/prompts/` |
| 模型怎么接的 | `app/providers/llm/` |
| 数据存哪 | `app/models/` + `app/database/` + `data/app.db` |
| 怎么证明"质检过" | `app/services/qc_grounding.py`（证据门禁） |
